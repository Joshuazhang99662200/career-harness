# Initial Setup

GM 与 EM 进入同一个 Setup。完成工作区配置后，再按本宿主的角色继续。

## 1. 检查连接并恢复已有工作区

告诉用户「CareerHarness 会检查你现有的飞书求职工作区。如果没有，会自动创建所需的数据表和自动化。请完成飞书授权。」

1. 检查官方 `lark-cli`，Windows 运行 `lark-cli.cmd auth status --json --verify`。复用现有有效身份。缺安装、用户授权或必要权限时停在对应步骤，提供最小范围的官方安装或授权指引。
2. 读取私有 `settings.json`。有已验收 Base 时，用现挂身份验证访问、所需字段和 Workflow 绑定，正常就恢复。映射或权限发生变化则重新对账。已有绑定访问失败时先恢复原 Base 的访问权。
3. 用户授权自动配置后，按 [飞书配置流程](feishu-provisioning.md) 执行发现、复用或创建、对账、激活、触发验收与绑定。Base 和 Workflow 管理使用用户授权。GM、EM 共用一个已注册且经写入验收的 Bot。已有候选无法消歧时，请用户选择。非破坏性的建表、补字段或启用 Workflow 沿用同一次授权。
4. 按真实回执告知「飞书连接成功」「正在查找已有工作区」「已复用／新建工作区」「数据表和字段已验收」「操作记录自动化已激活」。四条 Workflow 启用和逐条触发成功分别验收。Dream 调度按宿主独立验证。

## 2. 准备材料

1. 在已验收的 Base 读取现有材料。仅缺失时向用户收集简历 PDF、技能栈 Markdown 或个人事实 Markdown。
2. Setup/GM 把三份资料分别存入 `简历模板`、`技能栈`、`事实整理`。用 `材料ID` 和 `岗位类型` 定位现有材料。EM 直接复用材料，必要时让当前会话进入 Setup/GM 职责。
3. 对话补充事实时，一次讨论一段经历，核实职责、推进过程及可验证结果，允许跳过。显示「正在导入个人材料」前先确认需要导入且取得资料。写成功后核对附件和访问权限。

## 3. 选择招聘平台

按 [招聘平台能力路由](platform-capability-routing.md) 探测此宿主，并显示每个平台的当前状态。问用户希望使用哪些平台，可多选、跳过及以后修改。选项包括 BOSS 直聘、猎聘、智联招聘、LinkedIn、企业招聘官网 / ATS 和小红书。若私有配置已经确认选择，直接复用。

默认使用 `routing_mode = auto`。只有用户主动指定入口时，进入高级覆盖模式。用户可禁止某种方式。单个平台受限时标出具体原因，继续配置其他平台。[EM 执行链路](em-execution.md) 按通过验收的入口运行。

## 4. 恢复角色和业务设置

- 确认本宿主承担 GM、EM 或兼任，已有值直接复用。分立宿主分别验证 CLI、真实 Base 访问及同一个 Bot 的适用权限。
- 求职方向、年限、地点、远程条件、薪资口径、硬筛与排除词，沿用已确认设置。
- 每个平台与总配额、搜索日程、简历模板及允许改写范围，缺失时保留待确认状态。
- 被动超时的启用、计时口径、目标状态和需要暂停的情况，以及招聘方明确拒绝后的处理权限，按本人设置执行。自动化达到可用时才按用户已确认的日程运行。

## 5. 开始使用

Base 映射、四条 Workflow 触发与必要角色权限通过后，按材料与业务设置的准备程度开放对应任务。平台设置未确认或被跳过时，仍可处理 Base 中已有岗位。Setup 无需访问或联系任何招聘方。

GM 继续 [生成流程](../roles/GM.md)，EM 继续 [执行流程](../roles/EM.md)。外发读同一岗位最新的 `批准状态`、当前招呼语和有效简历。只有本人可设置 `已批准` 和 `已拒绝`。独立报告 Dream 和 10 日谈各自的调度与运行结果。已验证的现有工作区可告知「已找到 CareerHarness 工作区，配置有效，继续上次任务。」
