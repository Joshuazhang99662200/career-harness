# 渲染与 ATS 策略

GM 出简历 PDF 时使用本页：渲染路径、排版约束与关键词覆盖口径。

## 按本次模式选择渲染路径

先按 [简历入口](../optimizer/SKILL.md) 确定模式。保留原结构和目标模板填充使用 [模板修改与逐页验收](optimizer/template-tailoring.md)，通用 renderer 不得覆盖已选母版。全盘重写按本人选定布局制作；可以选择 [resume-builder](https://github.com/StoneLL1/resume-builder)(MIT) 或仓库的 `jobagent harness render`，但安装可用性与实际输出须另验。不自动改成单页、换字体或套新主题。

渲染工具只决定怎么排，不决定写什么：

| 阶段 | 归属 |
|---|---|
| JD 需求拆解、视角路由、内容改写、按 [质量门禁](optimizer/quality-gates.md) 自查 | **GM** |
| 经本人选择的新布局、对应编译与 PDF | **所选渲染工具** |
| PDF 文字、顺序、页数与内部批注核对 | `jobagent harness check-pdf` |

### 边界

- 交给渲染工具的内容必须是 GM 已按质量门禁自查过的最终正文。
- resume-builder 的 `claim-map` 只记录“这条信息有没有出处”，不代替 GM 的事实自查；它的「重包装」口径比 [事实边界](../optimizer/SKILL.md#事实边界) 的「不扩大语义」略松，以本项目口径为准。
- 它的「裸描述 ≈ 没写、引导给数字」会制造数字压力。材料里没有数字就留白，不得估算。
- 它自带的 PDF 解析与信息收集流程不使用；个人资料只来自材料表。

其余上游复用边界见 [oss/resume-builder.md](oss/resume-builder.md)。

## 排版约束（ATS 安全）

新选布局时优先以下可解析方案；已锁定模板不因这些建议自动改版，先检查实际抽取和阅读顺序，存在冲突时说明并交本人选择：

- 单栏正文。不使用多栏分栏排版。
- 不把正文放进表格。表格单元格的阅读顺序在解析器之间不一致。
- 不把任何正文信息放进页眉、页脚或文本框。联系方式必须出现在正文首屏。
- 不使用图片承载文字，不使用图标代替文字标签。
- 章节标题使用常规词汇（工作经历、项目经历、教育背景、技能），不要用创意标题。
- 日期格式在全文内保持一致，推荐 `YYYY.MM`，区间用连字符。
- 字体使用常见无衬线或衬线字体，正文字号不小于 10pt。
- 页数以本次选定方案为准，不按经验年限强设一页。超出区域先精简表达，删减可追溯，不任意缩字号或改边距。
- 选模板时优先单栏、无表格、无照片（resume-builder 的 `billryan` / `luooofan` 属此类）；双栏高密度模板会被解析器读错顺序。

## 输出格式

- 交付格式默认 PDF，并同时保留可编辑源文件，便于后续复用。
- 文件名不得包含本人手机号、身份证号或住址。推荐 `姓名_目标岗位_版本.pdf`。
- 本地生成物落在 `candidate/variants/` 下，该路径已被 gitignore；核对通过后放进岗位表的 `简历cv（PDF）`。不要写入仓库其他位置。

## 关键词覆盖的口径

关键词覆盖指“JD 关键词是否已被材料里有依据的表述覆盖”，不是“关键词出现了几次”。

- 一个关键词只有出现在**材料里有依据的实质性主张句内**时，才算覆盖。
- 独立的技能堆砌区、关键词罗列段、白色隐藏文字**一律不算覆盖**，并且禁止生成。
- 同义词与缩写按 JD 的写法归一（例如 JD 写 `K8s` 就用 `K8s`），但归一化不得改变主张的语义范围。
- 未被覆盖的关键词作为缺口说明；需要本人补充时在对话里问，不得通过塞词消除缺口。

当提高覆盖度的唯一办法是编造或放大主张时，正确做法是保留缺口。

## 核对

渲染完成后运行 `jobagent harness check-pdf`：正文能否被文本抽取还原、抽取顺序是否与最终正文一致、页数是否超限、是否带内部批注。任何一项不通过就不交付。
