# 飞书共享来源：宿主侧验收交接

## 本次验收对象

本次交接验证已实现的最小飞书读写适配器能否在生成侧与一个执行侧宿主中使用。三方仍是 GPT/生成侧、执行 Agent 侧、人类；Muse、GrokBot、WorkBuddy 是同一执行侧的可替换实现。

以交接消息给出的 GitHub 分支和完整 commit SHA 为准，启动时读回实际 SHA，不使用浮动 main 或混合版本。验收分支为 `codex/feishu-shared-source-acceptance`，基于 `main@32575f37c1b56eda58dfe39a6929c3f81501f44b`。代码只新增共享来源适配入口，不迁移或删除旧 Worker 业务记录。

已验证的是本机两个逻辑角色共用同一来源的 Schema、条件查询、字段回写与历史回读；独立宿主接入、事件长连接、Agent 唤醒及真实招聘动作仍需分别验收。本交接不授权发送、投递、修改在线简历、代写本人批准、修改分享权限或重新配置定时任务。

## A：先做只读能力验收

- 记录宿主名称/版本、承担角色、实际源码 SHA、可用工具和验收时间。凭证、真实材料及表 ID 只留本人的私有配置，报告不暴露凭证。
- 验证同版本 Python runtime 与官方 Lark CLI 是否可运行；`executable` 使用宿主内实际安装的原生二进制，不能复制另一台机器的绝对路径。缺依赖时明确报告，不宣称宿主已支持。
- 核验现有授权与已关联 Base。CLI 先 `auth status --json --verify`，仅在明确缺授权/scope 时按最小范围处理；不重新初始化已有配置，不切换身份规避权限。
- 使用本人已有表/字段配置读取实时 Schema。生成侧与执行侧共享同一语义映射，写入白名单按角色区分；不得默认新建表、字段或平行队列。
- 生成侧只读查询“匹配理由为空且满足既有待评估条件”的岗位；执行侧只读查询既有 `批准状态 × 处理进度` 条件。二者都记录准确筛选范围、实际条数、has_more、表版本及恢复点，不执行平台动作。
- 取数大小复用已确认的业务参数。若仅做有界探针，明确其演练范围，不将探针数值登记成个人配置。续页带 expected_table_revision，来源版本变化时重新读取并对账。

可调用入口：

```text
jobagent feishu schema --config <private-config.json> --table <table-key>
jobagent feishu query --config <private-config.json> --request <query.json>
jobagent feishu get --config <private-config.json> --table <table-key> --record-id <record-id>
```

安装模式按 harness bootstrap 执行，不依赖开发者仓库或全局 jobagent。配置及请求的精确类型见随包 `schemas/feishu.py` 和共享来源 reference。

## B：仅对获授权的合成记录验证两侧回写

在本人已明确授权的准确测试记录和字段范围内执行。已有授权直接复用；当前宿主无法关联授权/目标时先报告，不新建另一条记录或选择真实岗位替代。

1. 生成侧 get 测试记录，取得完整映射内容摘要。
2. 生成侧 patch 仅修改获授权的合成测试内容，核对 status、verified、dispatched，并读取实际结果。
3. 执行侧在自己的宿主 get 同一条共享记录，核对能看到生成侧的新内容。
4. 执行侧使用新摘要 patch 同一获授权内容字段，生成侧再 get 验证结果一致。
5. 如需验证历史，范围仅限该记录，串行读取原生 history；保存 before/after、实际时间和操作者返回形态，不从显示名猜 actor 类型。
6. 材料/批准/真实进度字段保持原授权边界。不要使用测试来发送招聘消息，也不要使用 patch 冒充平台动作已完成的证明。

```text
jobagent feishu patch --config <private-config.json> --request <patch.json>
```

若写入返回 unknown/unverified、超时或回读不一致，先查当前共享记录；不要重复派发。写前内容摘要不是服务端原子 CAS，验收顺序执行；多个写者的共享协调需另外核实。

## C：单独核验事件与持续宿主能力

本次已有 CLI 事件目录实测不含目标 Bitable record changed。不要编造 event consume 命令；先检查当前宿主版本和实际能力。

若已有合法配置的接收组件，提供其代码/版本、真实订阅状态及脱敏事件样例，验证事件只能提示刷新当前飞书记录。记录“事件收到”“宿主被提示/唤醒”“实际开始读取”三个不同结果。没有订阅或无后台能力时标记未接通，并继续通过当前状态查询验收，不报告实时联动成功。

启用新应用订阅、持续服务、外部写入或真实任务变更，先提供准确方案并核对本人授权。不能读取或输出 appSecret/access token 来完成交接。Dream、Search Memory 发布/消费和招聘发送不因本次只读/合成回写验收自动获准。
