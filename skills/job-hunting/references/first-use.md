# Initial Setup：在对话里接入一张多维表格

第一个开始 setup 的 Agent 按本页在对话里完成接入。三方约定见 [多维表格契约](bitable-contract.md)；接入后按当前角色加载 [GM.md](../roles/GM.md) 或 [EM.md](../roles/EM.md)。

**轻量原则：** 能问一句就不建表单，能复用已有设置就不重问；不要求本人审阅长文档。

## 1. 先读状态，不重开

先找本人私有的 `settings.json` 与私有表格配置。已有的设置直接复用，只补缺的那几项；本人没要求调整就不重问。

## 2. 前置依赖

检查飞书或钉钉 CLI 是否已安装、授权是否有效（飞书：`lark-cli auth status`）。不满足就停在这里，告诉本人如何安装与授权，等本人完成后再继续；不以其他方式绕过。钉钉 CLI 的表格读写尚未核验，遇到时如实说明。

## 3. 问清当前角色

一条消息问一题：这个宿主承担 GM、EM，还是两者兼任？只要本人允许，同一宿主可以兼任。GM 与 EM 分立时，再问本机 MCP bridge 的启动方式（脚本位置与 Tunnel 标识），只记进私有 `settings.json`，不写进仓库，也不在每个任务重建。

## 4. 收集个人资料，写进材料表

1. 请本人上传简历，或直接聊经历。
2. 聊经历时一次只聊一段，语气友好：
   - 先复述理解：引用本人原话，用自己的话说出理解，问“对吗”；本人纠正的以本人为准。
   - 再基于本人的回答往下问一两层：负责哪块、怎么做到、结果怎么衡量。不用固定问卷。
   - 一条消息最多两三个小问，末尾写“不想展开可以回复「跳过」”；本人说跳过就换下一段。
3. 把简历放进材料表的 `附件`，把全部个人资料由你自由组织成一份 md，放进 `准确全文`。之后只在这份 md 内增删改。
4. 不把整份 md 交给本人逐条确认；写错的地方会在本人驳回或修改招呼语时被捕捉，再由 GM 修正。

## 5. 对照表格结构

用 CLI 读取本人 Base 的表与字段，按契约里的五个语义域对上号，把表、字段坐标和 Bot 身份记进私有配置。缺表、缺字段或类型对不上时，向本人展示具体差异；新增或修改表、字段、选项、Workflow 都要本人明确同意后才做。主结构保持不变，日后按本人需要再扩展。

## 6. 求职与寻源设置：一题一题地选

一条消息一题，给出选项并总留“其他：自己填”。选项尽量由材料推断，并附一句依据。

1. 求职方向（多选，要能落到可搜索的岗位名称）。
2. 工作年限、最低税前月薪、城市（含是否接受远程）、不考虑的方向。
3. 招聘平台（多选）。
4. 每个平台的 EM 执行方式（每平台一题）：
   - 云端浏览器：可做定时任务，但封号率高；
   - MCP：猎聘、领英；
   - 浏览器插件：随时可用，稳定安全。
5. 多久搜一次；每个平台每轮搜多少。

答案写进私有 `settings.json`，之后各轮只读取。

## 7. 就绪

用两三句话告诉本人：当前角色、已接上的表、材料表里已有什么、寻源设置是什么、还缺什么。然后按角色开始第一轮。
