# 飞书最小接入与两侧共用协议验收

日期：2026-11-19。源码基线：`57ba6ba0cd3dd736a7cf02e919db74045e72dd06` 加当前未提交工作树。本轮实现的是共享飞书读取/字段回写能力及生成侧、执行侧共用调用协议；没有部署两个独立宿主、开启事件订阅或执行招聘发送，也没有删除原 Worker 代码。

## 已实现

| 入口 | 能力 | 证据 |
|---|---|---|
| `jobagent feishu schema` | 私有语义字段映射与实时 Schema 核对 | `FeishuGateway.schema`；真实岗位 Schema 可读 |
| `jobagent feishu query` | 原生 AND 条件、显式投影/批量大小、有界分页 | 生成侧/执行侧共用查询；续页核对表版本 |
| `jobagent feishu get` | 读取单条当前映射内容及摘要 | 实测同一条合成记录，供两侧读写 |
| `jobagent feishu patch` | 角色字段白名单、写前摘要检查、字段类型/选项校验、正向回读 | 两侧各一次真实更新成功，并最终回读一致 |

契约集中在 `src/jobagent/schemas/feishu.py`，CLI 传输/服务在 `src/jobagent/bridge/feishu_gateway.py`，入口在 `src/jobagent/cli/feishu.py`。不依赖 SQLite 或已有 ask/approval 行，不建立新的业务账本。Skill 按需加载[共享来源协议](../skills/job-hunting/references/feishu-shared-source.md)，两侧使用同一组类型与命令。

角色白名单是宿主调用约束，不能代替飞书身份鉴别。查询/回写结果均不授予外发权；现有内容、审批、附件、平台查重及发送回读保护不因本适配器存在而被移除。

## 真实只读验收

- 正常凭据环境的用户身份验证可用；沙箱环境无法读取既有配置，因此没有启动重复授权。
- 表目录与岗位字段 Schema 成功读回；岗位表当前只有一个未筛选的既有视图，查询可直接使用原生条件，不必新增视图或任务表。
- 生成侧演练条件为“匹配理由为空”：限定读取两条，返回 2 条且 has_more=true，不能宣称已遍历全部待办。
- 执行侧演练条件为“已批准且进度为招呼语初稿”：返回 0 条且 has_more=false。该结果只适用于这组演练条件，不证明其他阶段没有可执行事项，也不把它设为全部执行语义。
- 每次演练读取大小仅用于本次有界验证，没有激活或改写本人的频次、Batch Size、预算或其他动态参数。
- 再次实际读取相同待评估条件的两页：第一页 2 条、第二页 1 条，表版本一致、记录互不重复，第二页 has_more=false。该结果对应本次条件查询，不是对全表或其他阶段待办的宣称。

## 授权合成记录的写入验收

本人在本次对话明确允许在现有“记录”表新增一条合成测试记录。实际新增且保留一条带集成测试标记、无真实岗位关联的记录，然后：

1. 生成侧以当前摘要更新测试内容，回读 verified=true。
2. 执行侧读取同一共享记录，使用新摘要再次更新测试内容，回读 verified=true。
3. 最终重新读取，内容摘要与执行侧回执一致。

实际岗位、批准状态、处理进度和招聘会话未修改。新增记录 ID、准确测试内容、请求配置及回执保存在本人私有验收目录，不写入公开文档。

创建后的第一次读取与写前读取之间出现内容变化，被摘要保护拒绝，没有派发该次更新。核验同一记录当前状态后继续原测试，未重新创建记录。该现象说明创建请求成功不能证明字段已完成异步落地；陈旧版本拒绝需按当前来源恢复。

## 原生历史与事件能力

对上述唯一合成记录查询原生历史，得到一条 create、两条 update，包含 revision、时间及更新字段 before/after；创建条目的 field_changes 为空。历史内容与两次实际更新一致。

当前 CLI 输出的 operator 为显示名字符串；本次 AI 调用使用用户身份，两侧历史显示相同操作者。不能据此区分 Human/生成 Agent/执行 Agent，也不能将这些更新直接学习为本人偏好。稳定身份与宿主操作来源仍需单独接线和验收。

实测官方 CLI 1.0.91 的事件目录有 25 项，不包含目标 Bitable record changed。不能调用不存在的 event consume 入口。官方 [Node SDK](https://github.com/larksuite/node-sdk) 文档提供 WSClient/EventDispatcher 长连接路线，但应用后台订阅、权限、真实事件 fixture、持续运行环境及宿主刷新触发本轮尚未核验或启用。

事件功能不阻塞本次原生条件查询/字段回写验证；本适配器不将事件或快照当作三方共享消费游标。各侧每轮仍需从当前飞书记录筛选未完成工作。

## 明确的限制

- 写前检查与写入之间存在并发窗口，回执标记 pre_read_only；这不是服务端原子 CAS，不提供跨宿主独占执行权。
- 摘要是 mapped_content_sha256，不是飞书原生记录版本，也不是本人批准证明。
- 只支持普通 text/select 字段更新；附件上传、创建业务岗位/材料、平台发送和业务状态迁移不在该最小适配器的自动能力中。
- 已批准材料不能原位改写；本人批准字段不会被本适配器修改。生成新版本和重新审批继续按业务协议处理。
- 写入派发/回读失败返回 unknown/unverified，不自动重复请求，必须先核验当前记录。返回 verified 只说明请求字段回读一致。
- 本轮在同一本机环境以两个逻辑角色验证接口，不能将此写成 Muse/GrokBot/WorkBuddy 与生成宿主已经分别部署联动。
