# 猎聘投递：只投在线简历（猎聘专属）

本文只适用于猎聘。BOSS 和智联通过浏览器发送首条招呼语，材料、审批和执行路径都不同，不适用本文。本文记录的是猎聘投递的模型、面板（前端）应当如何呈现，以及在线简历的优化方向。只写说明，不涉及后端核心代码的修改。

## 投递模型

- **只投在线简历。** 猎聘的一键投递只能投平台上的在线简历，不能投按岗位定制的 PDF。没有首条招呼语，也没有随投递附带的消息。
- **在线简历是全局唯一的一份。** 对所有猎头、所有岗位展示的是同一份，不能按岗位或按人定制。
- **对方看到的是查看时的最新版本。** 某个岗位投递时是 A 版，猎头在 B 版上线后才打开，看到的就是 B 版。所以投递只决定“投给谁”，决定不了“对方看到什么”。

因此猎聘有两类互相独立的批准：

| 批准什么 | 范围 | 说明 |
|---|---|---|
| 投递 | 逐个岗位 | 本人逐项批准“把在线简历投给这个岗位”。勾选不等于批准，一键投递只执行已批准的项。 |
| 在线简历版本 | 全局 | 改一次会影响所有已投、未投岗位，风险更高；走已有的在线简历修改流程（提案、提问、本人批准、放行、回读记账），每条内容都要有已确认的证据。 |

## 面板（前端）呈现

已经做到的：

- 猎聘岗位不显示招呼语、拟发送文本框、重新生成等招呼语相关内容。
- 详情里的流程节点是“评估匹配 → 批准投递 → 投递并核实”，没有“写招呼语”。
- 确认投递页写明“投递的是猎聘平台上的统一在线简历，不是逐岗准备的 PDF 文件”，并提供在线简历预览入口。
- 失败、重试、成功的文案都用“投递”，不用“发送”。

还需要在前端或接线层面处理的：

- **在线简历预览打不开。** 仓库模板的适配器对在线简历预览直接返回“实际在线简历来源尚未接入”，面板只能显示“在线简历暂时打不开”。需要接到宿主提供的在线简历只读来源（例如已保存的在线简历快照），只读展示，不写平台。
- **说明“对方看到的是最新版本”。** 确认投递页应写明：对方查看时看到的是当时的最新在线简历，不一定是现在这一版。
- **投递前显示读回的版本。** 确认投递时展示投递前读回的在线简历版本（时间与摘要），和批准时看到的版本不一致时提示，并按下面“待本人决定”的规则处理。
- **结果按平台回执显示。** 平台回执为“您已投递过该职位”时显示为已投递，不显示为失败；结果不明时显示“待核实”，不提供重试。

目前面板对猎聘的投递批准、执行清单和一键投递还不可用：保存决定时会提示猎聘投递审批尚未接入，执行清单会把猎聘岗位排除并写明原因，也不会为猎聘生成待办。这几项需要后端接通后，前端才能启用；在那之前前端保持禁用，并说明原因。

## 在线简历的优化方向（仅方向，尚未实现）

能做的优化是：用记忆信号汇总已投递、已批准、有回复的猎聘岗位 JD 的共性要求，对这一份通用在线简历做泛化的修改，让它对整体投递目标最优。

约束：

- **只能调整，不能新增。** 优化只体现在已确认事实的取舍、排序、强调和措辞上；不能因为 JD 常出现某个关键词，就加入本人没有确认过的能力或经历。
- **防止过拟合。** 只有一份通用简历，过度贴合某一类已投岗位，可能损害其他方向的投递。目标应按投递方向加权，不能只看投得最多的那一类。
- **按查看时间归因。** 评估某个简历版本的效果时，回复要归到对方查看时的版本，而不是投递时的版本。样本不足时如实标注，不下结论。
- **修改仍逐版批准。** 每次修改都是一个新的全局版本，必须本人批准该版本，回读核对后才算生效。

## 待本人决定

1. **批准后在线简历变了怎么办。** 建议：投递批准时记下当时的在线简历版本，投递前读回一次。如果变化来自本人批准过的在线简历更新，之前批准的投递继续有效；如果是来源不明的变化（例如在平台上手动修改），就停下来重新询问。
2. **每日投递上限和间隔。** 应从本人的私有配置读取，不写进公共默认值。
